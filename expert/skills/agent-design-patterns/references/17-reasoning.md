# 17 · 推理技术（Reasoning Techniques）

> 溯源：《智能体设计模式》第 17 章 推理技术 · 板块：可靠性与工程化
> 证据基准：本节内容除特别标注外，均为书中原文确认 [F]。

## 1. 模式定义

推理技术让智能体的内部推理过程显式化：通过多步逻辑推理与问题分解，智能体能够拆解问题、考虑中间步骤，并得出更稳健、准确的结论 [F]。其核心原则是在推理阶段分配更多的计算资源——允许智能体或底层大模型拥有更多处理时间或步骤来分析问题并生成响应；智能体可迭代优化、探索多种解决路径或调用外部工具。在需要深入分析和思考的复杂问题上，这能显著提升准确性、连贯性和健壮性 [F]。

## 2. 工作机制

智能体的思考是「思考-行动-观察」结构化循环 [F]：

```
输入: 复杂问题（无法一步直出答案）
  ↓
[思考 THINK]  生成文本思考：分解问题、制定计划、分析现状
  ↓
[行动 ACT]    从预定义动作集中选择行动
              （在线搜索 / 信息检索 / 代码执行 / 给出最终答案）
  ↓
[观察 OBSERVE] 获取环境反馈（搜索结果 / 网页内容 / 执行输出）
  ↓
  循环往复，可自我纠错与回溯，直到智能体认为
  已获得最终解决方案并执行「结束」动作
  ↓
输出: 最终答案 + 可审计的推理轨迹
```

书中核心技术族 [F]：

| 技术 | 机制要点 |
|---|---|
| 链式思维 CoT | 生成一系列中间推理步骤而非直接给答案；显式分解难题，透明可调试；few-shot 示例或「逐步思考」指令激发 |
| 树式思维 ToT | 在 CoT 基础上扩展为树状结构：探索多条推理路径，可回溯、自我纠错，比较多种方案后择优 |
| 自我纠错 | 对生成内容与中间思考自我评估，发现歧义、信息缺失或错误后迭代优化，将质量控制嵌入生成流程 |
| 程序辅助语言模型 PALM | 模型生成并执行代码，把精确计算、逻辑操作交给确定性编程环境，结果再转回自然语言 |
| 可验证奖励强化学习 RLVR | 新型推理模型在推理前分配可变「思考时间」，在数学、代码等有标准答案的问题上试错学习生成有效长推理链，无需人工监督 |
| ReAct | CoT + 工具交互：思考-行动-观察循环，根据反馈动态调整计划，比线性 CoT 更灵活健壮 |
| 辩论链 CoD / 辩论图 GoD | 多个模型协作辩论、互相批评；GoD 将论点建模为动态非线性网络，结论取最有力、最可验证的论点集 |
| MASS | 多智能体系统搜索：先优化各智能体单体提示，再优化交互拓扑，最后全局优化系统级提示 |

**推理扩展定律** [F]：该定律描述 LLM 性能与推理阶段所分配计算资源的关系。与训练扩展定律不同，它关注模型生成答案时的动态权衡。核心观点：通过推理阶段增加计算资源（如生成多个候选答案并筛选），小模型也能获得优异结果；这不一定依赖更强硬件，而是采用更复杂的推理算法，如多样性搜索或自洽方法。「思考预算」充足的小模型甚至可超越简单推理的大模型。它挑战「模型越大越好」的直觉，为智能体系统的高效、经济部署提供理论依据——开发者可据此在性能、响应延迟和运维成本之间做更精细的资源分配决策。

## 3. 适用场景与不适用场景

| 适用 ✅ | 不适用 ❌ |
|---|---|
| 复杂问答：多跳问题需整合多源数据与多条推理路径，延长推理时间有助信息综合 [F] | 一步可答的简单事实问题：直出即可，展开推理徒增时延与成本 [E] |
| 数学问题求解：拆分为更小的可解部分，代码执行实现精确计算与结果验证 [F] | 强时延敏感的实时响应：思考预算与响应速度冲突（除非与 16 联动权衡） [E] |
| 代码调试与生成：解释理由、逐步定位问题，据测试结果迭代优化（自我纠错） [F] | 输出确定性优先的流程化任务：显式推理引入不必要的变异性 [E] |
| 战略规划：权衡多种方案、后果与前提条件，据实时反馈调整计划（ReAct） [F] | |
| 医学诊断 / 法律分析：分阶段阐述推理过程，调用外部工具取数，自我纠错保一致性 [F] | |

## 4. 选型决策要点

1. **书中经验法则** [F]：问题过于复杂、无法一次性解决，需要分解、多步逻辑、外部数据或工具交互、战略规划和适应时，优先采用推理技术；适用于「思考过程」与最终答案同等重要的任务。
2. **思考频率按任务调整** [F]：知识密集型任务（如事实核查）通常每步都插入思考以保证逻辑流畅；决策型任务（如环境导航）可灵活插入思考。
3. **单路径 vs 多路径** [F]：传统 CoT 仅生成单一推理路径，难以适应复杂问题；需要比较方案、回溯纠错时升级到 ToT 或具备自我纠错能力的推理模型。
4. **单体 vs 协作** [F]：单一智能体推理存在偏见与盲区，CoD/GoD 类多模型辩论框架代表从单一智能体到多智能体协作的转变；MASS 则自动优化多智能体系统的提示与拓扑。
5. **思考预算是资源决策** [E]：推理扩展定律表明更多思考时间换来更强能力，但思考预算直接消耗时延与成本——应与资源感知优化（16）联动，按问题复杂度分配思考量。

## 6. 反模式与坑点

1. **简单问题过度推理** [E]：对一步可答的问题展开长链思考，时延与 token 成本徒增且引入跑偏空间；推理技术应保留给无法一次性解决的复杂问题（书中经验法则的反面）。
2. **CoT 单路径依赖** [F]：传统 CoT 仅生成单一推理路径，难以适应复杂问题；关键决策应引入 ToT 的多路径探索或可回溯的自我纠错机制。
3. **只推理不验证** [F]：纯文本推理在算术与逻辑上不可靠——PALM 的价值正是把精确计算交给确定性编程环境并对结果做验证。
4. **把中间思考当最终答案** [E]：CoT 中间步骤可能包含被否决的分支与错误假设；交付用户的应是审查后的最终答案，但完整轨迹应留存供审计与调试（书中将透明可调试列为 CoT 优势）。
5. **思考预算失控** [F]：推理模型可生成更长、更动态的推理链，若无预算上限，思考时间与成本可能失控；须与资源感知优化（16）联动设置上限。

## 7. 与其他模式的组合

- **推理（17）+ 工具使用（05）**：ReAct 将链式思维与工具交互结合，形成思考-行动-观察核心循环，据环境反馈动态调整计划 [F]。
- **推理（17）+ 反思（07）**：自我纠错嵌入推理过程，对中间思考自我评估并迭代优化，形成质量控制闭环 [F]。
- **推理（17）+ 规划（04）**：CoT 内部独白制定连贯计划，将复杂目标拆解为可执行动作序列 [F]。
- **推理（17）+ 资源优化（16）**：推理扩展定律的「思考预算」是资源分配对象——按问题复杂度动态分配推理算力，小模型加充足思考预算可逼近甚至超越大模型效果 [F]。
- **推理（17）+ 多智能体（10）**：CoD/GoD 用多模型辩论与论证网络超越单链思维、减少偏见；MASS 自动优化多智能体提示与交互拓扑 [F]。
- **推理（17）+ RAG（06）**：检索增强为推理提供事实锚点；DeepSearch 即「生成查询 → 检索 → 反思迭代」的完整示范 [F]。

## 8. 评估指标

- **结果导向**：复杂任务终答准确率（多跳问答、数学求解、代码调试的正确率）；答案连贯性与健壮性 [E]。
- **过程导向**：推理轨迹质量（是否真实分解问题、中间步骤逻辑一致）；自我纠错触发率与纠错有效率；思考-行动-观察循环步数（过多说明初始计划质量差或检索质量低）[E]。
- **成本维度**：每正确答案的推理 token 成本——从推理扩展定律视角，比较「思考预算投入」与「准确率增益」的边际收益，判断预算分配是否处在高效区间 [F]。
