# 评审修正指南：已有 Agent 应用审核（Review Guide）

> 溯源：《智能体设计模式》全书 + FAQ · 类型：方法论指南
> 证据基准：除特别标注外均为书中原文确认 [F]；标注 [E] 为工程实践推断。
> 用途：任务类型「评审审核」时加载本文件。输入为应用代码/提示/配置路径，输出为体检报告 + 修正方案。

## 一、评审修正 SOP（5 步）

```
STEP 1 摸底       通读代码/提示/配置，识别已用模式与整体架构
      ↓ 产出：架构现状描述（用了哪些模式、缺哪些）
STEP 2 对照体检   按第二节检查表逐项核对，标记 缺失/误用/过度设计
      ↓ 产出：问题清单（每项含证据位置：文件/行/提示段）
STEP 3 定位根因   将问题归位到六环节：提示 / 工具 / 记忆 / 护栏 / 异常 / 评估
      ↓ 产出：根因分析（症状→环节→书中对应模式）
STEP 4 分级修正   P0 安全与正确性 → P1 效率与质量 → P2 优化
      ↓ 产出：修正方案（按级排序，每项含验证方法）
STEP 5 验证闭环   按评估指标 + 轨迹审查验证修正效果
      ↓ 产出：评审报告（问题/根因/修正/验证结果四列表）
```

**铁律**：先只读诊断，后出方案，经用户确认再动代码（远程运维同口径）；不做相邻优化 [E]。

## 二、审核检查项（10 项）

| # | 检查项 | 典型症状 | 溯源 |
|---|---|---|---|
| 1 | 目标漂移 | 行为偏离原始目标；无法说清成功标准 | 第 11 章 |
| 2 | 模式误用 | 该用规划却硬编码；该用路由却全塞单 prompt；单 Agent 够用却堆多 Agent | 第 2/6 章 |
| 3 | 提示缺陷 | 含糊冗余、缺约束、缺示例轨迹、缺输出格式 | 附录 A |
| 4 | 幻觉风险 | 无 RAG 锚定、无反思核查，编造事实 | 第 4/14 章 |
| 5 | 记忆错乱 | Session/State/Memory 混用；长期知识污染会话上下文 | 第 8 章 |
| 6 | 工具安全隐患 | 无权限控制；错误被静默吞掉；工具描述含糊导致误调用 | 第 5/18 章 |
| 7 | 护栏缺失 | 敏感操作未经审批自动执行；无输入输出过滤 | 第 13/18 章 |
| 8 | 异常脆弱 | 单点失败导致整体崩溃；无重试/降级/求助 | 第 12 章 |
| 9 | 上下文浪费 | 大段知识内联提示；无关信息挤占窗口 | 第 16 章 |
| 10 | 不可评估 | 无轨迹日志、无评估指标、失败无法定位 | 第 19 章 |

## 三、六环节根因定位表

| 环节 | 对应检查项 | 对应模式（修正方向） |
|---|---|---|
| 提示 | #1 #3 | 系统提示六要素重写（附录 A）；目标重定义（13） |
| 工具 | #2 #6 | 工具定义规范化（05）；路由分流（02）；错误处理三策略（14） |
| 记忆 | #5 | 三层记忆重构（08）；长期知识出窗（16） |
| 护栏 | #6 #7 | HITL 挂点补齐（15）；输入输出过滤（18） |
| 异常 | #8 | 重试/降级/求助（14）；受控失败设计 [F] |
| 评估 | #4 #10 | RAG+反思补齐（06/07）；指标与轨迹（19） |

## 四、分级修正标准

- **P0 · 安全与正确性**（立即修）：检查项 #6 #7 #8 + #4 幻觉；涉及数据安全、越权、崩溃、事实错误。
- **P1 · 效率与质量**（尽快修）：#1 #2 #3 #5 #10；影响目标达成与产出质量。
- **P2 · 优化**（排期修）：#9 + 成本类；不影响正确性的效率提升。

## 五、示例场景

### 场景 B · 客服机器人答非所问 + 幻觉 [E·典型问题综合]

- **症状**：频繁编造不存在的产品信息；跨轮上下文错乱。
- **摸底**：单 prompt 直出架构，无检索、无反思、单一 dict 存全部上下文。
- **体检**：#4 缺 RAG 锚定与反思 → 幻觉；#5 记忆混用（客户画像与会话记录同 dict）→ 上下文污染；#10 无轨迹 → 无法定位哪轮开始编造。
- **根因**：记忆环节 + 评估环节缺失。
- **修正**：P0 加 RAG（产品手册语料 + 来源归因）+ 反思（内部批评者核查事实性陈述）；P1 重构三层记忆（Session 会话 / Memory 客户画像分离）；P1 补轨迹日志。
- **验证**：结果导向——答对率（金标准集）前后对照；轨迹审查——事实性陈述是否均走 RAG 链路、批评者是否真实运行。

### 场景 C · 多步骤数据处理 Agent 中途崩溃 [E]

- **症状**：处理到第 4 步失败即整体崩溃；无日志无法定位。
- **摸底**：提示链 4 步线性串联，无异常处理，无状态持久化。
- **体检**：#8 无重试/降级/求助 → 单点崩溃；#10 无轨迹 → 不可追溯；#5 无 State 持久化 → 无法断点续跑。
- **根因**：异常环节 + 评估环节缺失。
- **修正**：P0 每步工具调用包异常处理（重试 N 次→换工具→升级求助）；P0 加轨迹记录；P1 State 落盘支持断点续跑。
- **验证**：注入故障用例（工具超时/返回异常），确认「恢复或显式失败」而非静默崩溃；续跑从断点开始而非从头。

## 六、输出模板（评审任务的交付结构）

```markdown
# {应用名} 智能体评审报告
1. 架构摸底（现状描述：已用模式/缺失模式）
2. 体检结果（10 项逐条：✅通过 / ⚠️问题[证据位置] / ➖不适用）
3. 问题清单与根因（症状→环节→对应模式，四列表：问题/根因/修正建议/级别）
4. 分级修正方案（P0/P1/P2 排序，每项含验证方法）
5. 验证结论（指标前后对照 / 轨迹审查结果）
6. 遗留风险与建议（未覆盖项明说，不静默跳过）
```
