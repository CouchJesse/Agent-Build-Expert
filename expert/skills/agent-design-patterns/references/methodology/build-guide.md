# 构建指南：从零新建 Agent 应用（Build Guide）

> 溯源：《智能体设计模式》全书 + 结论章 · 类型：方法论指南
> 证据基准：除特别标注外均为书中原文确认 [F]；标注 [E] 为工程实践推断。
> 用途：任务类型「构建指导」时加载本文件 + `decision-tree.md`，按阶段输出设计要点与架构方案。

## 一、可操作原则（8 条）

### P1 · 目标与边界先行（第 11 章 [F]）
先定义目标、成功标准、失败条件与越界清单，再谈模式选型。目标须 SMART（明确可衡量）。无明确目标的 Agent 必然发生目标漂移。

### P2 · 按复杂度选模式，拒绝过度设计（第 2 章及结论 [F]）
能单步就不链式（01），能线性就不并行（03），能单 Agent 就不多 Agent（10）。模式复杂度必须与任务复杂度匹配。

### P3 · 提示即章程（附录 A / FAQ [F]）
系统提示必须含六要素：①角色与目标 ②工具定义（功能描述 + 使用方法）③约束与规则（不得做的事）④流程指令（先计划再执行类）⑤示例轨迹（成功思考-行动-观察循环样例，可显著提升可靠性）⑥输出格式。

### P4 · 记忆三层分离（第 8 章 [F]）
Session（跟踪每次会话）/ State（会话临时记事本）/ Memory（MemoryService 长期知识）职责清晰、不混用；长期知识不得污染会话上下文。

### P5 · 先反思后交付（第 4/14 章 [F]）
输出必经「检查你的工作」或「内部批评者」反思环节，与 RAG 事实锚定配合降低幻觉。质量、准确性和细节比速度成本更重要时才启用 [F]。

### P6 · 高风险必有人把关（第 13/18 章 [F]）
删除、外发、交易、付费等操作必须人类审批（HITL 四干预点：计划审批/工具确认/歧义解决/终审）；护栏（输入输出过滤、权限校验）前置而非事后补救。

### P7 · 失败要出声、可追溯（第 12/19 章 [F]）
错误显式处理（重试/换工具/求助升级），全程留轨迹（智能体轨迹 = 思考+行动+观察完整日志），结果可评估、可回溯。静默吞错与静默崩溃都是设计失败。

### P8 · 组合显式声明取舍（结论章 / 第 20 章 [F]）
多模式协作要讲清「为何这样组合」，暴露而非掩盖权衡（延迟 vs 质量、成本 vs 准确、自主 vs 可控）；按优先级收敛范围。

## 二、构建流程（五阶段）

```
阶段 1  目标定义      → 阶段 2  模式选型      → 阶段 3  架构设计
                                              ↓
阶段 5  验证与迭代    ←  阶段 4  实现与护栏
```

**阶段 1 · 目标定义**：回答「目标/成功标准/失败条件/越界清单/高风险操作」五问（见 decision-tree.md 第 0 节表格）。

**阶段 2 · 模式选型**：走 `decision-tree.md` 主干树，产出「模式组合清单 + 每个模式的入选理由」。

**阶段 3 · 架构设计**：产出架构说明，须包含：
- 模式组合图（哪个模式在哪个环节）
- 系统提示六要素草案（P3）
- 工具清单（名称/功能描述/参数/错误处理/安全级别）
- 记忆三层设计（什么信息进 Session/State/Memory）
- HITL 挂点清单（哪些操作前暂停）
- 评估指标（结果导向 + 过程导向）

**阶段 4 · 实现与护栏**：按架构生码（可调「生成代码」任务类型），强制执行：
- 代码安全护栏（禁删除/外发/越权/无确认执行；高风险处 `# SAFETY:` 人工确认挂点）
- 密钥环境变量读取
- 异常处理三策略（重试/降级/求助）[F]
- 轨迹日志（verbose / events 遍历 / state 留痕）

**阶段 5 · 验证与迭代**：按各分章第 8 节指标验证；轨迹审查确认模式真实生效（如「先计划后执行」在轨迹中可观察到）。

## 三、构建阶段检查项（10 项）

| # | 检查项 | 通过判据 | 溯源 |
|---|---|---|---|
| 1 | 目标/成功标准/失败条件/边界四要素齐全 | 四要素均成文且可检验 | 第 11 章 |
| 2 | 复杂任务已用 Planning/提示链拆解 | 步骤清单存在且逻辑有序 | 第 6/1 章 |
| 3 | 模式选型与任务复杂度匹配、无过度设计 | 每个模式有触发信号理由 | 第 2 章 |
| 4 | 工具定义完整 | 名称/功能描述/参数说明/错误处理齐全 | 第 5 章 |
| 5 | 系统提示六要素齐全 | 逐项核对无缺 | 附录 A |
| 6 | 记忆三层齐备、职责清晰 | 无混用（长期知识不入会话窗口） | 第 8 章 |
| 7 | 高风险操作有 HITL 审批 + 输出过滤 | 高风险清单逐项有挂点 | 第 13/18 章 |
| 8 | 工具失败/超时有应对策略 | 重试/换工具/求助三策略至少其一 | 第 12 章 |
| 9 | 评估指标已定义 | 结果导向 + 过程导向双维度 | 第 19 章 |
| 10 | 智能体轨迹可记录 | 思考/行动/观察全程留痕 | 第 19 章 |

## 四、示例场景

### 场景 A · 客户咨询智能体（从零新建）[E·综合书中多章]

**需求**：管理客户咨询——感知问题细微差别、访问知识库、与订单系统交互、主动澄清、预见后续需求（书简介场景 [F]）。

**阶段 1 目标定义**：
- 目标：准确解答咨询并完成查询/操作类请求；成功标准：答对率 ≥ 90%、高危操作 0 未审批执行。
- 高风险操作：退款、投诉处理、对外发送通知 → 全部挂 HITL。

**阶段 2 模式选型**（走决策树）：
- Q1 多步任务（理解→检索→答复/操作）→ Q2 流程已知但分路径 → **路由(02)**（简单咨询/复杂技术/账单争议分流）
- Q3 需知识库与订单系统 → **工具使用(05)** + 事实锚定 **RAG(06)**
- Q4 准确性优先（对外答复）→ **反思(07)**（内部批评者核查）
- Q5 跨轮对话 → **记忆管理(08)**（Session 记会话、Memory 记客户画像）
- Q7 高风险操作 → **HITL(15)** + **护栏(18)**
- Q8 生产部署 → + **异常恢复(14)** + **评估(19)**

**阶段 3 架构要点**：系统提示含六要素（角色=客服专家；约束=不得承诺退款结果）；工具三件（kb_search / order_query / notify_send[SAFETY:发送前人工确认]）。

**取舍声明**：咨询流程可预枚举故用路由而非规划（P2）；单智能体足以承载（无需多智能体）；反思仅对外发答复启用（成本权衡）。

## 五、输出模板（构建指导任务的交付结构）

```markdown
# {应用名} 智能体设计方案
1. 目标与边界（五问表）
2. 模式选型（决策树走查记录 + 组合清单 + 理由）
3. 架构设计（组合图/系统提示草案/工具清单/记忆设计/HITL挂点）
4. 评估方案（结果+过程指标）
5. 取舍声明（P8）
6. 检查项自评（10 项逐条 ✅/❌）
```
