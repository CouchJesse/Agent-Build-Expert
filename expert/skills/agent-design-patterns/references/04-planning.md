# 04 · 规划（Planning）

> 溯源：《智能体设计模式》第 6 章 规划 · 板块：核心执行与任务分解
> 证据基准：本节内容除特别标注外，均为书中原文确认 [F]。

## 1. 模式定义

规划模式让智能体将复杂的高层目标拆解为一系列可管理、顺序化的小步骤，并制定从初始状态逐步迈向目标状态的行动策略。用户定义「做什么」（目标及约束），智能体自主规划「怎么做」——计划并非预先设定，而是根据请求动态生成。

## 2. 工作机制

规划的实质是**从初始状态到目标状态的行动序列发现**：

```
输入: 高层目标 + 约束条件（预算/人数/期限等）
  ↓
[理解] 初始状态（已知条件）与目标状态（成功判据）
  ↓
[生成] 计划 = 结构化的多步行动序列（非死板剧本，仅是起点）
  ↓
[执行] 按逻辑顺序执行各步骤，调用必要工具，管理依赖关系
  ↓
[适应] 新信息出现（场地不可用/供应商已满）→ 不直接失败，
       而是重新评估选项、调整剩余步骤（重规划 replanning）
  ↓
输出: 达成目标的综合结果
```

两个关键内在机制：

1. **适应性**：初始计划只是起点；智能体的真正能力在于根据新信息调整方向。
2. **灵活性与可预测性的权衡**：当解决路径已知且可重复时，约束智能体按固定流程执行更有效——限制自主性以换取结果可靠一致。是否采用规划模式，关键判据是「怎么做」需要探索，还是已经明确。

## 3. 适用场景与不适用场景

| 适用 ✅ | 不适用 ❌ |
|---|---|
| 流程自动化编排：新员工入职（创建账号→分配培训→协调部门） | 路径已知的固定流程：直接硬编码步骤链（用提示链第 01 章） |
| 结构化信息合成：复杂报告的分阶段生成（收集→摘要→结构化→迭代完善） | 单步可完成的请求：单一行动或工具即可解决 |
| 多步骤客户支持：系统化诊断→解决→升级流程 | 强一致性要求的确定性任务：需可预测、可重复输出 |
| 自主导航 / 机器人：状态空间遍历、路径优化（时间/能耗） | [E] 短链任务（2 步以内）：规划开销大于收益 |
| 深度研究：Google Deep Research 式迭代检索与综合 | |

## 4. 选型决策要点

1. **复杂度门槛**：用户请求过于复杂、无法通过单一行动或工具完成时，才采用规划模式（书中经验法则）。
2. **与提示链（01）的边界**：提示链是开发者预定义的线性步骤；规划是智能体动态生成步骤。步骤已知→提示链；步骤需探索→规划。
3. **与多智能体（10）的边界**：规划解决「步骤怎么拆」，多智能体解决「谁来执行」；单智能体可执行的计划无需多智能体。
4. **激发方式**：大模型擅长根据任务描述生成合理计划，但需在提示或任务要求中**明确要求规划步骤**（如「先制定项目符号计划，再执行」）。
5. **人审挂点**：计划生成后先向用户展示并征求批准（协同规划，Deep Research 的做法），符合 HITL 模式（第 15 章）。

## 5. 多框架代码模板

### 5.1 框架无关伪代码

```text
planner_agent = Agent(
    role = "规划与执行专家",
    goal = "先制定可执行计划，再按计划完成目标",
    instructions = """
      收到高层目标后：
      1. PLAN   生成结构化计划（编号步骤列表），展示给用户确认
      2. EXECUTE 按顺序执行每一步，调用所需工具
      3. ADAPT  某步失败或新信息出现时，从当前状态重新规划剩余步骤
      4. SYNTHESIZE 汇总各步产出，形成最终综合结果
    """
)
```

### 5.4 CrewAI（源自书中第 6 章实码 [F]，改写为骨架）

```python

import os
from dotenv import load_dotenv
from crewai import Agent, Task, Crew, Process
from langchain_openai import ChatOpenAI

load_dotenv()  # 密钥从环境变量读取

llm = ChatOpenAI(model="gpt-4-turbo")  # TODO(user): 按需更换模型

planner_writer_agent = Agent(
    role='文章规划与写作专家',
    goal='规划并撰写指定主题的简明、吸引人的摘要。',
    backstory='你是一名资深技术写手，写作前先制定清晰可执行的计划。',
    verbose=True,
    allow_delegation=False,
    llm=llm,
)

# 2. 模式接线：任务描述中显式要求「先计划、后执行」——
#    这是书中要点：规划行为需通过任务要求激发
topic = "强化学习在 AI 中的重要性"  # TODO(user): 替换为实际主题
high_level_task = Task(
    description=(
        f"1. 针对主题“{topic}”制定摘要的要点计划（项目符号列表）。\n"
        f"2. 根据计划撰写约 200 字的摘要。"
    ),
    expected_output="### 计划\n- 要点列表\n\n### 摘要\n- 结构化总结",
    agent=planner_writer_agent,
)

# 3. 执行入口：顺序处理流程
crew = Crew(agents=[planner_writer_agent], tasks=[high_level_task],
            process=Process.sequential)
result = crew.kickoff()

# 4. 观测与护栏：verbose=True 输出执行轨迹
print(result)
```

## 6. 反模式与坑点

1. **计划当剧本执行** [F]：把初始计划当死板剧本，遇障碍直接失败。正确做法是重新评估、调整剩余步骤。
2. **简单任务强上规划** [F]：路径已知可重复时仍用动态规划，引入不必要的不可预测性。应改用固定流程（提示链/硬编码）。
3. **未显式激发规划行为** [F]：期望模型「自动」先规划再执行。必须在任务描述或系统提示中明确要求「先制定计划」并规定计划格式。
4. **计划不经确认直接执行** [E]：高风险目标（外发、交易类操作）的计划应先经用户审批（HITL），否则计划偏差会被放大执行。
5. **重规划丢失已完成上下文** [E]：重规划应「从当前状态」出发，基于已完成步骤（past steps）调整剩余步骤，而非从零重来。

## 7. 与其他模式的组合

- **规划 + 工具使用（05）**：计划中每一步按需调用工具（搜索、API、代码解释器）——Deep Research 的核心形态 [F]。
- **规划 + RAG（06）**：研究类计划的信息收集阶段用 RAG 锚定事实，降低幻觉 [E]。
- **规划 + 反思（07）**：计划执行结果经反思审查，反馈触发重规划，形成迭代改进闭环 [F]（Deep Research 具备反思、规划和执行能力）。
- **规划 + HITL（15）**：计划生成后展示给用户审核和修改，实现协同规划 [F]。
- **规划 + 多智能体（10）**：Planner 生成计划后分派给专职智能体执行（研究员/写手/评论员）——书中结论章「自主 AI 研究助手」组合范式 [F]。

## 8. 评估指标

- **结果导向**：目标达成率（最终综合结果是否满足高层目标与约束）；计划完成度（已完成步骤 / 总步骤）。
- **过程导向**：重规划次数（过多说明初始计划质量差或环境剧变）；每步工具调用正确性；计划-执行一致性（实际执行是否偏离计划且未触发重规划）。
- **轨迹审查**：检查「先计划后执行」是否真实发生（轨迹中计划先于执行出现），而非一步直出结果 [E]。
