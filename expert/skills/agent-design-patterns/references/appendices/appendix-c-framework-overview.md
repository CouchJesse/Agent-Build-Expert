## 1. LangChain 与 LangGraph

**LangChain** 是开发 LLM 驱动应用的框架，核心优势是 LangChain 表达式语言（LCEL）：将各组件「管道化」串联成链，每一步的输出作为下一步的输入，适用于有向无环图（DAG）式的单向无循环工作流 [F]。典型场景：简单 RAG（检索→生成提示→获取答案）、摘要生成、信息抽取（提取 JSON 等结构化数据）[F]。

**LangGraph** 是基于 LangChain 构建的高级智能体系统库：将工作流定义为图结构，节点为函数或 LCEL 链，边为条件逻辑；最大优势是**支持循环**，可灵活实现任务重试、工具调用直到目标达成；显式管理应用状态，状态对象在节点间传递并不断更新 [F]。典型场景：多智能体系统（主管智能体分派任务、循环直到完成）、计划-执行智能体（制定计划→执行→按结果循环更新计划）、人类参与（流程等待人工输入后决定下一节点）[F]。

| 功能 | LangChain | LangGraph |
|---|---|---|
| 核心抽象 | 链（LCEL） | 节点图 |
| 工作流类型 | 线性（DAG） | 循环（支持环路） |
| 状态管理 | 每次运行基本无状态 | 显式持久状态对象 |
| 主要用途 | 简单、可预测流程 | 复杂、动态、状态化智能体 |

**如何选择** [F]：流程清晰、可预测、线性（从 A 到 B 到 C、无需回环）→ 选 LangChain（LCEL）；需要推理、规划、循环操作能力（调用工具、反思结果、尝试不同方案）→ 选 LangGraph 的循环与状态管理。

**并行流程示例（书中 LangGraph 实码的结构描述）** [F]：以 TypedDict 定义图状态（含主题与各生成结果字段）；定义三个 LLM 调用节点（分别生成笑话、故事、诗歌）与一个聚合节点；在 StateGraph 中从 START 分别向三个生成节点连边（并发扇出），再各自汇入聚合节点，最后连到 END；compile 后 invoke 执行，从状态中读取合并输出。

## 2. Google ADK

Google 的 Agent Development Kit（ADK）是高层次、结构化的多智能体应用开发与部署框架。与 LangChain、LangGraph 不同，ADK 更偏向**生产级智能体协作编排**而非底层智能体逻辑构建 [F]。

三层定位差异 [F]：

| 框架 | 定位 |
|---|---|
| LangChain | 最基础的组件与标准接口，适合串联模型调用、结果解析等操作 |
| LangGraph | 图结构实现更灵活的控制流，显式定义节点（函数/工具）与边（执行路径），支持复杂循环推理与状态管理，适合精细化智能体思维流程或多智能体系统 |
| Google ADK | 屏蔽底层图结构，提供**预设的多智能体架构模式**：内置 SequentialAgent、ParallelAgent 等智能体类型，自动管理智能体间控制流；以「团队」概念为核心，主智能体分派任务给专职智能体；状态和会话管理更隐式，无需手动传递状态对象 |

书中示例结构 [F]：用 LlmAgent 创建一个具备搜索增强能力的智能体——指定模型、名称、描述、指令（要求借助搜索回应查询）与工具列表（如搜索工具）；收到问题后智能体调用搜索工具获取实时信息并据此作答。相比 LangGraph 的显式状态传递，ADK 更适合快速搭建协作型智能体「工厂流水线」[F]。

## 3. CrewAI

CrewAI 是以**协作角色和结构化流程**为核心的多智能体编排框架：抽象层次更高，开发者无需定义底层图结构，而是定义团队成员及分工，框架自动管理智能体间的交互 [F]。

核心组件 [F]：

| 组件 | 职责 |
|---|---|
| Agent | 不仅有功能，还具备角色（role）、目标（goal）和背景故事（backstory），影响其行为和沟通风格 |
| Task | 分配给智能体的具体工作单元，包含描述和期望输出 |
| Crew | 团队容器，包含所有智能体和任务，执行预设流程 |

流程模式 [F]：顺序流程下任务按顺序传递；分层流程下由类似「经理」的智能体协调分派任务。书中示例结构：用装饰器方法返回一个 Crew 对象，注入智能体列表与任务列表，设置顺序流程并开启详细日志监控。与其他框架相比，CrewAI 不做 LangGraph 那种显式状态管理和流程控制，而是让开发者设计「团队章程」；ADK 提供全生命周期平台，CrewAI 专注智能体协作逻辑与团队模拟 [F]。

## 4. 其他智能体开发框架

| 框架 | 定位与优势 | 局限 |
|---|---|---|
| AutoGen | 以多智能体协作对话为核心，支持不同能力智能体间的复杂任务分解与协作；灵活的对话驱动 | 执行路径不确定性较高，对提示工程要求较高 [F] |
| LlamaIndex | 数据框架，专注将 LLM 与外部/私有数据源连接，擅长数据摄取与检索管道，适合 RAG 能力智能体 | 复杂控制流与多智能体编排不如专用智能体框架 [F] |
| Haystack | 开源框架，专注大规模、生产级搜索系统；可组合节点架构支持检索、问答、摘要管道；性能与可扩展性强 | 对高度动态和创造性智能体行为实现较为刚性 [F] |
| MetaGPT | 通过预设 SOP（标准操作流程）分配智能体角色和任务，模拟软件公司团队协作；结构化输出，适合代码生成等专业领域 | 高度专用，通用智能体任务适应性较弱 [F] |
| SuperAGI | 开源框架，智能体全生命周期管理：配置、监控和可视化界面，提升执行可靠性；生产级特性与故障处理 | 平台较复杂，可能带来更多运维和集成成本 [F] |
| Semantic Kernel | SDK，通过插件和规划器系统将 LLM 与传统编程代码集成，允许 LLM 调用原生函数并编排工作流，适合将模型作为推理引擎嵌入企业应用；与 .NET 和 Python 代码库无缝集成 | 插件和规划器架构学习曲线较高 [F] |
| Strands Agents | 轻量级 SDK，采用模型驱动方式构建和运行智能体，支持从对话助手到复杂多智能体系统；模型供应商兼容性好，原生集成 MCP 工具调用；简单灵活、易定制智能体循环 | 设计轻量，开发者需自行完善监控和生命周期管理等运维能力 [F] |

## 5. 选型总结

智能体框架生态极为丰富：从底层智能体逻辑库（LangChain/LangGraph）到高层多智能体协作平台（CrewAI、ADK），再到数据密集型场景（LlamaIndex）。开发者需根据项目需求**权衡底层控制力与平台易用性**，选择适合的抽象层级 [F]。

[E] 编者决策建议（按主导需求选型）：线性管道→LangChain；循环与状态控制→LangGraph；角色分工与团队模拟→CrewAI；生产级协作编排与企业集成→ADK / Semantic Kernel；数据检索为核心→LlamaIndex / Haystack；对话驱动协作原型→AutoGen；轻量模型驱动 + MCP→Strands Agents。另需评估：框架与既有技术栈的契合度、社区活跃度与文档质量、团队学习曲线。
