## 3. 各阶段详细计划

### 阶段 0 · 准备与基线（0.5 天）

- **目标**：确定打包规范、模板标准与目录结构基线，避免后续返工。
- **关键任务**：
  1. 读取 `skill-creator` 打包规范，确定 SKILL.md 的 frontmatter 与正文结构。
  2. 读取 `expert-manager` 规范，确认专家包对 SKILL.md 的格式要求，确保双产物兼容。
  3. 制定 `references/` 分章文件统一模板（模式名 / 定义 / 适用场景 / 选型决策 / 多框架代码 / 反模式 / 评估指标）。
  4. 制定代码模板规范（框架无关伪代码为主 + 少量框架实码，标注 API 版本）。
- **负责人**：WorkBuddy（AI）执行。
- **所需资源**：`skill-creator`、`expert-manager` 技能；原书 PDF。
- **风险及应对**：双规范格式要求不一致 → 先读两规范，以兼容 `expert-manager` 为优先。
- **验收标准**：技能包骨架目录 + 3 份模板（SKILL.md 模板、分章文件模板、代码模板规范）就绪。

### 阶段 1 · 核心模式样板（2 天）

- **目标**：完整构建 6 个核心模式作为样板，验证分层架构与模板质量，确立后续批量标准。
- **关键任务**：
  1. 编写 SKILL.md 正文（角色定位 + 21 模式速查表 + 选型决策树框架 + 参数契约 + 路由指令）。
  2. 逐模式编写 `references/` 分章文件（`Planning` / `Reflection` / `Tool Use` / `Multi-Agent` / `HITL` / `RAG`）。
  3. 每模式含多框架代码模板（LangChain/LangGraph + Google ADK + CrewAI 对照）。
  4. **先完成 1 个样板模式供评审，通过后再批量其余 5 个**（降低返工风险）。
- **负责人**：WorkBuddy 执行，项目负责人评审。
- **时间节点**：2026-09-21 ~ 09-23。
- **所需资源**：原书第 4 / 5 / 6 / 7 / 13 / 14 章；目标框架官方文档。
- **风险及应对**：代码模板 API 版本过时 → 标注版本、伪代码优先；模板深度不达标返工 → 样板先行、评审通过后再批量。
- **验收标准**：6 个分章文件齐全；SKILL.md 骨架可走通 5 类任务类型；代码模板语法正确；样板模式评审通过。

### 阶段 2 · 模式全量补齐（3 天）

- **目标**：按已定型的模板补齐其余 15 个模式，达到全量 21 模式。
- **关键任务**：
  1. 批量编写 15 个分章文件：提示链 / 路由 / 并行化 / 记忆管理 / 学习适应 / MCP / 目标监控 / 异常恢复 / A2A / 资源优化 / 推理技术 / 护栏安全 / 评估监控 / 优先级排序 / 探索发现。
  2. 补全 SKILL.md 速查表至 21 模式。
- **负责人**：WorkBuddy 执行。
- **时间节点**：2026-09-23 ~ 09-26。
- **所需资源**：原书对应章节；框架官方文档。
- **风险及应对**：批量编写质量波动 → 严格套用阶段 1 定型的模板，抽样复核。
- **验收标准**：21 个分章文件齐全、速查表完整、无模式遗漏。

### 阶段 3 · 方法论与附录（2 天）

- **目标**：落地「指导与评审」方法论与全部附录。
- **关键任务**：
  1. `methodology/build-guide.md`（8 原则 + 构建 10 检查项 + 场景 A）。
  2. `methodology/review-guide.md`（评审 SOP + 评审 10 检查项 + 场景 B / C）。
  3. `methodology/decision-tree.md`（模式选型决策树）。
  4. `appendices/` 下 7 个附录（提示工程 / 交互 / 框架速览 / AgentSpace / 命令行智能体 / 推理引擎 / 编程智能体）。
- **负责人**：WorkBuddy 执行。
- **时间节点**：2026-09-26 ~ 09-28。
- **所需资源**：需求规格 `BIZ-TECH-0001` 中已提炼的方法论；原书附录 A ~ G。
- **风险及应对**：附录内容与正文重复 → 附录仅保留正文未覆盖的扩展知识。
- **验收标准**：methodology 3 文件 + appendices 7 文件齐全。

### 阶段 4 · 脚本与资产（1 天，可选）

- **目标**：提供代码骨架生成脚本与视觉速览辅助。
- **关键任务**：
  1. `scripts/` 代码骨架生成脚本（按参数生成项目脚手架）。
  2. `assets/` 一图速览 SVG（可选）。
- **负责人**：WorkBuddy 执行。
- **时间节点**：2026-09-28 ~ 09-29。
- **风险及应对**：脚本与主技能耦合 → 脚本作为可选增强，不阻塞核心交付。
- **验收标准**：脚本可运行、生成的骨架可跑通。

### 阶段 5 · 打包与验收（1 天）

- **目标**：完成双产物打包、脱敏合规审查与全量验证。
- **关键任务**：
  1. `skill-creator` 打包 SKILL.md 技能包。
  2. `expert-manager` 转化为专家包。
  3. 脱敏全文扫描（0 个人姓名 / 公司名 / 品牌标识）。
  4. 引用溯源核对（知识点标注章节可回溯原文）。
  5. 代码安全护栏验证。
  6. 端到端验证（`/adp` 触发 + 5 类任务类型实测）。
- **负责人**：WorkBuddy 执行，项目负责人终验。
- **时间节点**：2026-09-29 ~ 09-30。
- **所需资源**：`skill-creator`、`expert-manager`、脱敏扫描脚本。
- **风险及应对**：专家包加载失败 → 回退至仅技能包交付，专家包排期修复。
- **验收标准**：见「整体验收标准」。

## 4. 整体风险登记表

| 风险 | 等级 | 影响 | 应对措施 |
|---|---|---|---|
| 框架 API 版本过时 | 中 | 代码模板失效 | 标注版本；伪代码优先；构建时检索最新文档 |
| 上下文窗口限制 | 高 | 全量内容无法一次加载 | 分层架构：SKILL.md 精炼 + references/ 按需加载 |
| 脱敏遗漏 | 高 | 合规违规 | 构建后全文扫描校验（全局规则） |
| 工作量与质量失衡 | 中 | 返工 / 延期 | 核心模式先行做样板，验证后再批量 |
| 双产物格式不兼容 | 中 | 专家包无法加载 | 先读两规范，优先兼容 expert-manager |
| 编号冲突 | 低 | 文档混乱 | 用脚本统一分配 NN |
| 多框架维护成本 | 中 | 内容臃肿 | 代码模板控篇幅：伪代码 + 1~2 框架实码 |

## 5. 整体验收标准

1. `SKILL.md` 技能包 + 专家包**双产物**可被 WorkBuddy / CodeBuddy 加载。
2. `/adp` 命令 + 关键词**双通道**可触发。
3. **5 类任务类型**（构建指导 / 评审审核 / 模式选型 / 生成代码 / 讲解模式）实测均可用。
4. **全量 21 模式 + 7 附录 + methodology 两指南 + 决策树**齐全。
5. **脱敏扫描通过**（0 个人 / 公司 / 品牌标识）。
6. **引用溯源**可回溯原书章节。
7. **代码安全护栏**生效（不生成删除 / 外发 / 越权 / 无确认执行的代码）。
8. 命名 / 编号 / 归档符合 `file-storage-compliance` 规范。
