## 7. T6 · 构建指导实测（场景：RAG 客服智能体）

按 `build-guide.md` 五阶段流程与输出模板，对裁定预告场景执行构建指导：

### 7.1 阶段 1 · 目标与边界（五问）

| 问题 | 回答 |
|---|---|
| 目标 / 成功标准（SMART） | 准确解答客户咨询并完成查询类请求；答对率 ≥ 90%，高危操作 0 未审批执行 |
| 失败条件 | 编造产品信息（幻觉）率 > 5%；单次会话超时 30s；越权执行高危操作 |
| 越界清单 | 不得承诺退款结果；不得透露其他客户信息；不得自行发送对外通知 |
| 高风险操作 | 退款、对外通知、订单取消 → 全部挂 HITL |

### 7.2 阶段 2 · 模式选型（决策树走查）

| 决策点 | 走查结论 | 入选模式 | 触发信号理由 |
|---|---|---|---|
| Q1 能否单步完成 | 否（需理解→检索→答复/操作） | — | 多步且含外部操作 |
| Q2 步骤已知？ | **已知但分支多路径**（简单咨询 / 技术问题 / 账单争议） | **路由(02)** | 咨询类型可预先枚举，故用路由而非规划（P2 拒绝过度设计） |
| Q3 需外部数据？ | 需产品知识 + 订单数据 | **工具使用(05)** + **RAG(06)** | 私有知识须事实锚定 |
| Q4 质量要求？ | 对外答复，准确性优先 | **反思(07)** | 内部批评者核查事实性陈述 |
| Q5 跨轮？ | 是 | **记忆管理(08)** | Session 记会话、Memory 记客户画像 |
| Q7 高风险？ | 是（退款/通知） | **HITL(15)** + **护栏(18)** | 四干预点覆盖 |
| Q8 生产部署？ | 是 | + **异常恢复(14)** + **评估(19)** | 失败出声 + 可评估 |

**组合清单**：`路由(02) + 工具使用(05) + RAG(06) + 反思(07) + 记忆管理(08) + HITL(15) + 护栏(18) + 异常恢复(14) + 评估(19)`

### 7.3 阶段 3 · 架构设计要点

- **组合图**：路由分流 → 「RAG+工具」并行取数 → 反思核查 → 记忆写入 → 输出过滤；高危分支前置 HITL 闸门。
- **系统提示六要素**：角色=客服专家；目标=准确解答；工具定义（3 件）；约束=不得承诺退款结果 / 不得外发；流程=先查后答；示例轨迹（成功问答样例）；输出格式（结论 + 来源）。
- **工具清单**：`kb_search`（产品知识库，只读）、`order_query`（订单查询，只读）、`notify_send`（对外通知，**SAFETY：发送前须人工确认**）。
- **记忆三层**：Session=当前会话轮次；State=本轮检索到的订单/工单临时上下文；Memory=客户画像与历史偏好（不进入会话窗口）。
- **HITL 挂点**：退款审批、对外通知审批、跨客户查询拦截。
- **评估指标**：结果导向=答对率、幻觉率、高危操作拦截率；过程导向=检索命中率、反思触发率、轨迹完整率。

### 7.4 阶段 4–5 与检查项自评

| # | 检查项 | 自评 |
|---|---|---|

### 7.5 取舍声明（P8）

- **为何用路由而非规划**：咨询类型可预先枚举，用规划属过度设计（P2）。
- **为何单智能体**：领域单一，多智能体将产生大量空闲 Agent（decision-tree 第 4 节误选表）。
- **反思仅对外发答复启用**：延迟翻倍的代价仅在准确性刚需处支付。
- **未纳入 RAG 的语料**：训练数据内已有的通用知识不检索，避免「RAG 当万能药」误选。

**判定**：构建指导任务类型**实测通过**，10 项检查项可逐条落地。
